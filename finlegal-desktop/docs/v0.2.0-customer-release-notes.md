## What is new

FinLegal-Chat v0.2.0 strengthens the release and desktop-workspace foundation for enterprise evaluation. The release introduces a more controlled build and publication process, clearer artifact verification, improved desktop safety boundaries, and a commercial-readiness path for data residency and partner governance.

### Signed platform installers

Windows installers are built for the intended release version and are designed to be signed with the organization’s Authenticode certificate. Customers can inspect the Windows publisher identity, certificate chain, timestamp, and signature status before installation.

macOS applications and disk images are designed to use Apple Developer ID signing and notarization when the approved Apple credentials are configured. Customers should verify the Developer ID identity, hardened-runtime status, notarization result, and stapled ticket before installation.

Linux packages include SHA-256 release manifests. Package-level Linux signing remains subject to the distribution and customer policy described in the release evidence.

### Build provenance and artifact verification

The release workflow produces SHA-256 manifests, release manifests, software-component evidence, and GitHub artifact attestations. These records are intended to connect each published artifact to the expected source revision, workflow, repository, and build context.

Customers can independently verify downloaded artifacts using the published hashes and the FinLegal validation instructions. Where GitHub artifact attestations are published, customers with the appropriate GitHub CLI and repository visibility can run the approved attestation-verification command against the expected repository.

> **Important:** A valid signature or provenance attestation helps establish publisher identity, post-signing integrity, and build origin. It does not prove that the application is free of vulnerabilities, suitable for every regulated process, or compliant with a customer’s specific legal obligations.

### Enterprise data-residency readiness

The v0.2.0 program includes a documented data-residency and global commercial readiness framework. It defines the future release gates for region-aware deployment, tenant and data-plane separation, residency decisions, encryption and key-management controls, backup locality, subprocessors, identity integration, retention, deletion, and audit evidence.

The desktop preview stores workspace state locally on the customer device. That local-preview behavior should not be interpreted as a complete cloud data-residency control or as a substitute for the production enterprise residency commitments in the applicable order form, data-processing agreement, and service documentation.

Before production Tier-1 financial-institution deployment, FinLegal will complete the applicable identity, tenant-isolation, retention/deletion, regional processing, support, incident-notification, assurance, and customer-evidence gates.

### Safer desktop workspace

The desktop workspace now includes safer renderer and IPC boundaries, blocked unexpected navigation and permission requests, a restrictive Content Security Policy, validated local workspace persistence, drag-and-drop source intake, duplicate-document handling, keyboard workflow support, and a guided Windows installation experience.

The evidence-first interface continues to emphasize source material, review status, audit readiness, and defensible analysis workflows. Supported source types include PDF, DOCX, TXT, Markdown, and CSV files.

## Customer verification before installation

Customers should download the installer only from the approved FinLegal release channel or an approved enterprise software-distribution process. Before installation, record the release version, artifact name, source SHA when provided, and SHA-256 hash.

Verify the platform signature or notarization status where applicable. Compare the local file hash with the published manifest. Review the release manifest, software-component evidence, and provenance-attestation result when supplied. Test the installer in the customer’s approved environment before broad distribution.

If the signature is invalid, the publisher identity is unexpected, the hash differs, the provenance verification fails, or the artifact was obtained from an unapproved location, do not install it. Preserve the file and contact the FinLegal security or support contact listed in the customer agreement.

## Known limitations

This release is a controlled enterprise preview and should not be represented as a complete production financial-institution deployment. The current preview does not by itself provide cloud-enforced multi-tenant isolation, SAML/OIDC/SCIM administration, customer-managed keys, universal Apple Silicon packaging, Linux package signing for every distribution policy, or independent SOC 2/ISO 27001 certification.

The release notes should be read together with the applicable enterprise agreement, data-processing terms, security documentation, residency schedule, and support commitments. Availability of signing, notarization, attestations, and residency features depends on the release artifact, configured environment, customer subscription, and approved deployment model.

## Support and feedback

For installation verification, security questions, enterprise data-residency requirements, GSI distribution coordination, or release-integrity concerns, contact **[FinLegal support/security contact]** and include the release version, platform, artifact filename, local SHA-256 hash, and relevant verification output. Do not send private keys, certificate passwords, customer documents, or confidential source material in a support ticket.
