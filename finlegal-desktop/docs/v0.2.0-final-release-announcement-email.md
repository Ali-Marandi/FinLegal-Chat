# Final v0.2.0 Release Announcement Email

**Subject:** FinLegal-Chat v0.2.0: Verified enterprise preview for GSI and financial-institution teams

**To:** GSI partner executives, GSI engineering leaders, General Counsels, Chief Compliance Officers, CIO/CISO stakeholders, and approved enterprise pilot teams

Dear colleagues,

We are pleased to announce the availability of **FinLegal-Chat Enterprise Workspace v0.2.0**, a controlled enterprise preview for approved GSI partners and financial-institution evaluation teams.

This release advances FinLegal-Chat from a desktop product preview toward an evidence-first enterprise workspace. It strengthens the release supply chain, improves the desktop security boundary, and provides a more disciplined path for partner-led validation, customer rollout, and future data-residency deployments.

## What v0.2.0 delivers

The release workflow is designed to produce platform-specific artifacts with the appropriate integrity and publisher controls. Windows installers are intended to be Authenticode-signed, macOS applications and DMGs are intended to use Developer ID signing and notarization when the approved release credentials are configured, and Linux artifacts are accompanied by SHA-256 manifests.

The release evidence package includes artifact hashes, release manifests, software-component evidence, and GitHub artifact attestations where those attestations are published. These records connect a release artifact to the expected source revision, repository, workflow, and build context. GSI and enterprise engineering teams should independently verify the downloaded artifact before installation and retain the verification output in the implementation record.

The desktop workspace also includes strengthened renderer and IPC boundaries, a restrictive Content Security Policy, blocked unexpected navigation and window creation, denied permission requests, validated local persistence, drag-and-drop source intake, duplicate-document handling, keyboard workflow support, and a guided Windows installation experience.

## Enterprise and data-residency context

v0.2.0 includes the commercial and technical readiness framework for region-aware deployment, tenant and data-plane separation, residency decisions, encryption and key-management controls, backup locality, subprocessors, identity integration, retention, deletion, and audit evidence.

The current desktop preview stores workspace state locally on the approved customer device. This behavior should not be interpreted as a complete cloud data-residency commitment or as a substitute for the applicable enterprise agreement, data-processing terms, residency schedule, and production deployment controls. Production Tier-1 deployment remains subject to separate architecture, identity, tenant-isolation, privacy, support, assurance, and customer-approval gates.

## GSI rollout invitation

GSI partners are invited to nominate engineering leads and Solution Architects for the v0.2.0 enablement cycle. FinLegal will provide the approved release evidence package, verification instructions, sandbox protocol, post-install smoke test, incident playbook, certificate-rotation procedure, customer notification template, and rollout communication materials.

Partner teams should use synthetic or approved de-identified data in the isolated sandbox, maintain separate test credentials and tenants, verify release integrity before redistribution, and route any non-standard security, residency, regulatory, contractual, or AI-output commitment to FinLegal for approval.

## Customer next steps

Approved enterprise clients should identify a technical owner, confirm the target operating system and endpoint-management path, open the required change record, download the artifact only from the approved channel, verify its signature or notarization and SHA-256 hash, and complete the post-install smoke test before pilot-user access is enabled.

Please contact **[FinLegal partner or security contact]** to request the controlled preview package, schedule a technical briefing, or discuss data-residency and customer-evidence requirements. When reporting a release-integrity concern, include the version, platform, artifact filename, local SHA-256 hash, source SHA if available, and verification output. Do not send private keys, certificate passwords, customer documents, or confidential source material.
